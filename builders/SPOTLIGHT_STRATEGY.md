# Spotlight strategy (Cohort I)

How this project earns **core-team attention** and **top builder support** without hype.

## 1. Lead with ecosystem ROI

QMS eng support is finite. Frame every demo around **hours saved for all teams**:

| Deliverable | Message to QMS |
|-------------|----------------|
| `@qms-passport/sdk` | “Stops `finalized` tag footguns and documents confirmation policy once.” |
| Migration Kit | “December reset is your announced pain — we export manifests for the whole cohort.” |
| PoUW cards | “Surfaces your differentiator on every tx, not another DEX clone.” |

## 2. Ship visible artifacts before Nov 18

Reviewers weight **working code** and **deployment**:

1. Public GitHub (this repo) — **day 0**  
2. Live alpha URL — **week 2**  
3. 90s screen recording: connect → faucet → QWAP → activity PoUW link — **week 2**  
4. npm or tagged release `@qms-passport/sdk@0.1.0` — **week 3**  
5. One other cohort project importing SDK (offer integration help) — **week 3–4**

## 3. Make QMS the hero

Copy and UI should say **“Powered by QMS PoUW”**, link whitepaper and docs, credit QWAP explicitly. Avoid branding that sounds like an official QMS product unless invited.

## 4. Concrete asks (easy for core team to say yes)

- PoUW JSON on explorer API ([POUW_DATA.md](../docs/POUW_DATA.md))  
- Pin Passport in `#builders` after alpha  
- Joint thread with @QWAP_xyz on onboarding funnel metrics  

## 5. Metrics to report in Discord updates

Weekly, short:

- Unique wallets connected  
- Completed onboarding steps (funnel %)  
- Manifest exports  
- SDK git dependencies / npm downloads  

## 6. What “not vibe-coded” means here

- Typed manifest schema + tests  
- Foundry tests for registry  
- Architecture + integration docs citing official QMS URLs  
- Honest limits (PoUW API gap documented)  
- Open license, no closed demo repo  

## 7. After selection

Offer to maintain **“Redeploy on new testnet”** workshop for cohort — positions you as infra partner, not single app.
